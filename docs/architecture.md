# Архитектура

Браузер и S3-клиенты обращаются к одному Go-процессу. Консоль работает на отдельном HTTP-порту, S3 — на отдельном endpoint. Оба используют хранилище метаданных bbolt и общий слой провайдеров.

## Запись

Файл делится на части по 8 МиБ. Каждая часть получает случайный nonce, шифруется AES-256-GCM и передаётся провайдеру. AAD связывает часть с идентификатором шифрования и её индексом. Метаданные содержат порядок частей и ссылки провайдера. Имя объекта не отправляется в имени зашифрованной части.

Объект публикуется атомарно в транзакции bbolt только после успешного сохранения всех частей и проверок контрольных сумм. Предыдущая версия содержимого доступна до этой транзакции. При ошибке известные временные части попадают в очередь очистки. Неопределённый результат сетевого запроса или аварийное завершение между внешней записью и фиксацией ссылки может оставить неучтённую часть у провайдера.

Условия If-Match/If-None-Match проверяются внутри транзакции публикации. Сетевые операции не удерживают глобальную блокировку записи БД. Для отдельной части используются отдельные блокировки, поэтому независимые файлы загружаются одновременно.

## Возобновление и очередь

Браузер хранит ID upload-сессии, связанный с бакетом, именем, размером, временем изменения и отпечатком начала/конца файла. Полная SHA-256 каждой части проверяется сервером. После перезагрузки пользователь повторно выбирает исходный файл: браузер не сохраняет его содержимое.

Одна очередь управляет всеми выбранными файлами. `maxFiles` задаёт количество одновременно активных файлов, `concurrency` — общий бюджет запросов частей. Планировщик отдаёт свободные слоты файлам с меньшим числом активных частей; добавленная партия не заменяет текущую. Ошибка и пауза затрагивают один файл. Выбор 16 файлов не создаёт 16×16 запросов.

Сессии сохраняются в bbolt. Незавершённые сессии истекают через 7 суток без обновлений, завершённые — через сутки. Завершение повторяемо в течение хранения сессии.

## Чтение

Читатель фиксирует снимок ссылок на объект и защищает его части от сборщика мусора до закрытия. Данные скачиваются с ограниченным параллельным упреждением, проверяются GCM и расшифровываются до выдачи клиенту. HTTP Range читает нужные участки; память зависит от числа потоков, а не от размера файла.

Для обычного PUT сохраняется полная SHA-256. Для параллельной загрузки через консоль сохраняется `tree_sha256`: SHA-256 от конкатенации бинарных SHA-256 частей в порядке файла. Это **другая** величина, не SHA-256 всего файла. Multipart ETag имеет вид MD5 от MD5 частей плюс `-N`; ETag не заменяет криптографическую проверку GCM.

## Долговечность

`master.key` содержит 32-байтовый ключ; `metadata.db` — каталог, ссылки, сессии, bcrypt-хеш и очередь очистки. Провайдер сам по себе не позволяет восстановить каталог. Потеря любого из этих двух файлов критична. Локальные части также входят в резервную копию.

Один каталог DATA_DIR обслуживает один процесс. Несколько реплик, распределённая блокировка, IAM и публичные бакеты не реализованы. GC работает раз в минуту; отказ удаления не удаляет ссылку из очереди.
