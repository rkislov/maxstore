# Совместимость S3

Endpoint по умолчанию `http://127.0.0.1:9000`, адресация **path-style**, регион клиента `us-east-1`. Одна пара ключей имеет административный доступ ко всем бакетам. Это профиль основных файловых операций, а не весь сервис Amazon S3.

## Реализованные операции

Бакеты: ListBuckets, CreateBucket, HeadBucket, DeleteBucket (только пустой), GetBucketLocation, ListObjects v1, ListObjectsV2. Листинг поддерживает prefix, delimiter, marker/start-after, max-keys, continuation-token и encoding-type=url. Имена бакетов: 3–63 символа a–z, 0–9 и дефисы; точки не поддерживаются.

Объекты: PutObject, GetObject, HeadObject, DeleteObject, DeleteObjects (до 1000 ключей, Quiet, индивидуальные ошибки), CopyObject и UploadPartCopy с диапазоном. Копирование выполняется потоком через шифрование, включая копирование между провайдерами. CopyObject — до 5 ГиБ, для большего размера используйте multipart copy. Отсутствующий ключ при DeleteObject считается успешно удалённым.

Multipart: CreateMultipartUpload, UploadPart, CompleteMultipartUpload, AbortMultipartUpload, ListParts и ListMultipartUploads. Части 1–10 000, размер 5 МиБ–5 ГиБ, последняя может быть меньше. Минимальный размер проверяется при завершении. Перечни частей/загрузок поддерживают пагинацию; delimiter для ListMultipartUploads не поддерживается.

Теги: Get/Put/DeleteObjectTagging и Get/Put/DeleteBucketTagging, до 10 уникальных тегов. Теги также принимаются через X-Amz-Tagging при PUT и создании multipart. Копирование поддерживает перенос тегов и REPLACE.

Метаданные: X-Amz-Meta-*, Content-Type, Cache-Control, Content-Disposition, Content-Encoding, Content-Language, Expires. CopyObject поддерживает MetadataDirective COPY/REPLACE. Условные PUT и CompleteMultipartUpload поддерживают If-Match/If-None-Match с атомарной проверкой перед публикацией. При копировании поддержаны условия по ETag и времени исходного объекта.

Чтение: ETag/Last-Modified, Range и стандартные условные GET через Go ServeContent. Подписанные URLs GET/PUT SigV4 поддерживаются до 7 суток; подпись заголовков допускает расхождение часов до 15 минут. Для HEAD возвращаются заголовки без скачивания частей.

Контрольные суммы обычного тела: X-Amz-Content-Sha256, Content-MD5, X-Amz-Checksum-SHA1/SHA256/CRC32/CRC32C. Несовпадение отклоняет публикацию, старый объект сохраняется. Дополнительные суммы multipart не собираются в полный checksum объекта: клиентам не следует запрашивать multipart checksum aggregation. ETag multipart — composite MD5 с суффиксом числа частей.

## Настройки AWS CLI

```sh
export AWS_ACCESS_KEY_ID='<s3_access_key>'
export AWS_SECRET_ACCESS_KEY='<s3_secret_key>'
export AWS_DEFAULT_REGION=us-east-1
export AWS_REQUEST_CHECKSUM_CALCULATION=when_required
export AWS_RESPONSE_CHECKSUM_VALIDATION=when_required
aws configure set default.s3.addressing_style path
aws configure set default.s3.max_concurrent_requests 4
aws --endpoint-url http://127.0.0.1:9000 s3 ls
aws --endpoint-url http://127.0.0.1:9000 s3 cp ./large.bin s3://my-backups/large.bin
aws --endpoint-url http://127.0.0.1:9000 s3 cp s3://my-backups/large.bin ./restored.bin
aws --endpoint-url http://127.0.0.1:9000 s3 sync ./folder s3://my-backups/folder
```

Настройки checksum отключают необязательный streaming checksum режим новых клиентов. Если клиент отправляет `aws-chunked`, STREAMING-* или CRC64NVME, сервер отвечает 501. Передавайте обычное тело с известным размером или multipart. Обычный HTTP Transfer-Encoding: chunked (без AWS обёртки) поддерживается Go-сервером.

## AWS SDK for Go v2

```go
client := s3.New(s3.Options{
    Region: "us-east-1",
    BaseEndpoint: aws.String("http://127.0.0.1:9000"),
    UsePathStyle: true,
    Credentials: credentials.NewStaticCredentialsProvider(accessKey, secretKey, ""),
    RequestChecksumCalculation: aws.RequestChecksumCalculationWhenRequired,
    ResponseChecksumValidation: aws.ResponseChecksumValidationWhenRequired,
})
```

Используйте `*os.File` или `bytes.Reader` как Body, либо менеджер multipart upload для больших потоков. В репозитории есть интеграционный тест с настоящим клиентом AWS SDK, включая Unicode-ключи, CRC32, метаданные, копирование, теги и массовое удаление.

## rclone

Пример конфигурации `rclone.conf` (подставьте ключи из своего credentials.json):

```ini
[maxstore]
type = s3
provider = Other
env_auth = false
access_key_id = <s3_access_key>
secret_access_key = <s3_secret_key>
region = us-east-1
endpoint = http://127.0.0.1:9000
force_path_style = true
acl =
no_check_bucket = true
```

```sh
rclone copy ./folder maxstore:my-backups/folder --transfers 4 --s3-upload-concurrency 4
rclone copy maxstore:my-backups/folder ./restored --transfers 4
rclone check ./folder maxstore:my-backups/folder --download
```

Создайте бакет заранее через консоль или S3 API. Пустой acl не запрашивает неподдерживаемую выдачу прав. Первая проверка на локальном провайдере позволяет отличить ошибки клиента от ограничений Telegram/MAX.

## За рамками версии

Версионирование и delete markers, ACL и публичный доступ, IAM/bucket policies, STS, lifecycle, replication, Object Lock, website hosting, S3 Select, access points, notifications, inventory, analytics и AWS-specific управление не реализованы. Нет virtual-hosted style, browser POST policy, SigV2, SigV4a, streaming chunk signatures/trailers и CRC64NVME. Такие параметры не следует передавать; известные неподдерживаемые операции возвращают 501.

SSE-KMS/SSE-C не реализованы: шифрование всегда выполняет MaxStore собственным ключом. Отправка AWS-заголовков шифрования не означает наличие этих режимов. Ограничения и ошибки документируются как ограничения MaxStore, а не как гарантии Amazon S3.

Справочные источники протокола: [S3 API](https://docs.aws.amazon.com/AmazonS3/latest/API/Welcome.html), [CopyObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CopyObject.html), [DeleteObjects](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObjects.html).
