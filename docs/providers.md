# Провайдеры

Каждый бакет закреплён за одним провайдером. Изменить его у существующего бакета нельзя: создайте другой и скопируйте объекты.

## Telegram

1. Создайте бота через [BotFather](https://t.me/BotFather).
2. Для личного чата откройте бота и отправьте `/start`. Для приватного канала добавьте бота с правами публикации и удаления сообщений.
3. Получите ID чата из `getUpdates` после сообщения боту или публикации в канале. Если бот использует webhook, `getUpdates` недоступен одновременно с ним. Лучше выделить отдельного бота для хранилища.
4. Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, перезапустите сервер.
5. Создайте в консоли бакет Telegram и проверьте загрузку и скачивание небольшого файла.

Адаптер использует `sendDocument`, сохраняет `file_id` и `message_id`, а при скачивании вызывает `getFile` для свежего пути. Зашифрованная часть занимает 8 МиБ + 28 байт. Это укладывается в ограничение скачивания 20 МБ облачного Bot API. В памяти находится ограниченное число частей.

Отправка регулируется интервалом: примерно 1,1 секунды для личного чата и 3,1 секунды для отрицательных ID групп/каналов. Ответы 429 повторяются до пяти попыток с `retry_after`. Потоки не отменяют ограничения частоты сообщений. Telegram обычно разрешает удалять сообщения только в пределах 48 часов; после удаления объекта старые части могут остаться у провайдера и в очереди очистки.

Реализация не использует аккаунт пользователя, MTProto, Telegram Desktop или cookies браузера.

Официальные источники: [Bot API](https://core.telegram.org/bots/api#getfile), [ограничения частоты](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this), [удаление сообщений](https://core.telegram.org/bots/api#deletemessage).

## MAX

Создайте бота через инструменты MAX для бизнеса, добавьте в чат, задайте `MAX_BOT_TOKEN` и `MAX_CHAT_ID`. Токен должен иметь доступ к отправке файлов и чтению сообщений этого чата.

Используется `https://platform-api2.max.ru`: запрос URL загрузки `/uploads?type=file`, multipart-загрузка, публикация токена вложения в сообщении. `attachment.not.ready` повторяется с задержкой. Для скачивания запрашивается актуальное сообщение и URL вложения. TLS проверяется; дополнительные доверенные сертификаты устанавливаются в окружение сервера.

Части отправляются как зашифрованные документы с расширением `.txt`; ограничения типов вложений и доступность нужно проверить с вашим ботом. Статус «Настроен» означает наличие конфигурации, а не успешный health check API. Автоматические тесты проверяют адаптер через TLS mock; они не подтверждают работу конкретного MAX-аккаунта.

Официальные источники: [загрузка](https://dev.max.ru/docs-api/methods/POST/uploads), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages).

## Локальный диск

Доступен всегда. Зашифрованные части сохраняются в `DATA_DIR/chunks`, метаданные в `DATA_DIR/metadata.db`. Подходит для проверки приложения без внешних сервисов; свободное место ограничено диском сервера.
