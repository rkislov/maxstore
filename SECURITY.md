# Безопасность

MaxStore предназначен для одного администратора. S3-ключи и bearer-токен дают полный доступ к хранилищу; разграничения по пользователям и бакетам нет. Приложение не проходило независимый аудит безопасности.

Части шифруются AES-256-GCM до передачи провайдеру. Метаданные, имена объектов и начальные учётные данные хранятся на сервере, а не шифруются тем же механизмом. Компрометация сервера и master.key позволяет расшифровать содержимое.

Для внешнего доступа используйте HTTPS. Храните DATA_DIR закрытым, резервные копии — отдельно, токены — в окружении/секретах деплоя. Не коммитьте `.env`, `credentials.json`, `master.key`, БД, логи и личные файлы. Потеря БД или ключа может сделать данные невосстановимыми.

Браузер использует HttpOnly/SameSite cookies, bcrypt и CSRF-заголовок; у входа есть ограничение неудачных попыток. S3 использует SigV4 и проверку даты. Скачивание может оборваться после отправки заголовков при ошибке удалённой части: клиент должен проверять успешное завершение и размер.

Об уязвимости сообщайте через приватный security advisory GitHub, если он доступен, либо сначала создайте issue без секретов и деталей эксплуатации с запросом приватного канала. Не прикладывайте токены, пароли или пользовательские данные.
